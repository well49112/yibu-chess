# 弈步 1.0.4 · 整盘并行分析

[APK 下载页面](https://github.com/well49112/yibu-chess/blob/apk-downloads/yibu-1.0.4-arm64.apk)

整盘深度复评、全局关键点缺失的分析，以及导入 / 本机棋谱的后台队列接入 `POST /sf/v1/review`。一盘棋提交一次完整 UCI 历史，使用 `profile=lightning`；并发数留给服务器自适应，20 核主机默认 16 路单线程 Worker。服务器严格搜满 22 层，不使用旧单步的 500ms 限制。多盘逐盘排队，盘内并行计算。

依据朋友公开的 UniChessServer 源码确认：批量响应只含每步摘要，没有讲解所需的实战分值、推荐 / 实战变化与比较标记。批量计算完成后，最多 4 路并发读取 `/sf/v1/analyze-move` 缓存详情，使用相同的 null 初始 FEN、无时间限制、MultiPV=1、PV=10 半步，避免因参数不同重新搜索。接口请求带随机标识，详情使用独立的步数后缀。

评级继续在手机按原算法计算，中文失误说明、后续思路和棋盘演示使用真实完整变化，不套用服务器摘要的评语。没有第二候选时保守处理 ! / !!。引擎变化或服务器缓存失效时，读取详情仍可能补算。

后台只保存未完成的步骤，中断后保留已有结果。摘要缺行或某步失败时保留其他成功步骤，并重试缺失部分；无效走法、错局和重复序号不能写入棋谱。已删除的棋谱不会被后台恢复，不覆盖更新的分析或重复结算 Elo。当前正在下的棋局仍增量分析新步骤，避免每着重提整盘。

手动复盘或最强对手能取消正在等待的后台请求，及时让出共享锁。整盘请求超时延长至 15 分钟，后台计算期间保持带超时的唤醒锁，取消或完成后释放。等待完整响应时如实显示“等待服务器结果”，结果返回后按保存数量更新进度；不显示虚构的按步计算进度。Android 前台服务原时限处理保留。

单步复评、缺失讲解的单步分析和最强对手继续原接口。单步 lightning 仍是 22 层 / 500ms / MultiPV=2；对弈 AI、课程及 UI 布局保留。沿用包名 `cn.yibu.chess`、原个人签名，versionCode 25，无数据库迁移，覆盖安装保留棋谱、Elo、设置、口令、课程与错题记录。ONNX Runtime 保持 1.24.3。

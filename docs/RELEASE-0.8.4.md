# 弈步 0.8.4 · 玩家关键点与具体讲解

[APK 下载页面](https://github.com/well49112/yibu-chess/blob/apk-downloads/yibu-0.8.4-arm64.apk)

关键点只挑选玩家已确认的失误和有具体学习价值的好棋。一般等价交换、直接回吃、普通阶段回顾及对手的棋步不再加入；有几个值得学的点就显示几个，最多五个。没有合适的点时提供说明与逐步复盘入口，不把“没有筛选到关键点”当作“这局没有失误”。

## 讲解改动

- 删除“本方的局面质量下降，关键要看对手怎样回应”的通用原因。原因先指出具体棋子、格子和合法参考变化，评价分数放在末尾。
- 比较实战与推荐：是否让某枚子能被直接吃掉、能否立即回吃、推荐是否给后/车/轻子增加压力，对手在参考线中怎样撤退，实战是否留出了推进中心并同时攻击多枚棋子的时间。
- 保留将杀、子力得失、吃过路兵真实被吃格与不同颜色的行棋方视角。只有分差、没有具体解释依据的棋步不选入关键点；不会把厘兵评价直接当作确定损失的子力。
- 普通兵、轻子和后的等价交换，即使评级为关键好棋，也不自动列入。真实弃子、双攻后吃掉目标和将杀路线继续保留；亮点由棋盘和变化证据支持，不能只靠高分或评级名称。
- 讲解版本从 3 升为 4。打开旧讲解时用已保存的引擎结果本地更新，不追加 Stockfish 搜索。

例如，在一条合法的类似开局变化中，Na6 与 b5 的说明会指出：b5 用兵攻击 c4 的白象，推荐线中白象走 Bb3 撤退；实战 Na6 后，白方有时间走 d4，把兵推进中心并同时攻击 c5 的黑象和 e5 的黑兵。这个测试用于验证解释所依据的棋盘事实，并不声称还原了截图的完整棋谱或重新测量了截图中的评价分数。

## 关键点与请求

关键点不再按双方分差筛选，也不补入“阶段回顾”或“对局如何结束”。只请求玩家所在颜色的棋步，完整历史仍随请求发送，后续演示仍包含对手的应对。有效的玩家缓存可以直接使用，即使没有对手棋步的分析缓存。

逐步复盘、手动查看每步、16 着参考变化、手动前进/后退、音效、AI 模拟思考和 Elo 结算沿用原有行为。0.8.3 的后台极速参数与 0.8.2 的耗时导出保留。

同包名、同个人签名，versionCode 17，可覆盖安装保留棋谱、Elo、口令和设置。棋步评级算法版本不变，只有中文讲解版本升级。
